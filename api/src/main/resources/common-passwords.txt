# Only entries of ten characters or more are worth keeping here: anything
# shorter is already refused by the @Size bound on the DTOs, so a shorter line
# in this file is dead weight that can never match.
#
# The list is drawn from the passwords that actually turn up at the top of
# public breach corpora once the short ones are removed. It is deliberately not
# a hundred thousand of them: the long tail is what a slow hash is for, and a
# file that has to be searched on every registration is a file somebody
# eventually loads into memory badly. What this catches is the handful of
# passwords a real person picks when told "at least ten characters" — which is
# almost always their old eight-character one with "12" on the end.
#
# Structural patterns (a single repeated character, a straight run of the
# keyboard or the digits) are not listed. They are generated in the validator,
# because listing every window of "1234567890123456789" by hand is how one gets
# missed.
